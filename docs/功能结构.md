# 随芯调功能结构

这份结构按用户任务组织，而不是按底层模块组织。后续 UI 和功能入口优先按这棵树推进。

当前优先级：

```text
1. 先保证控制台能看懂当前状态和下一步操作。
2. 再把策略中心拆清楚：应用配置、机型策略包、社区和迁移。
3. 诊断中心只放排障和检测信息，不混入配置入口。
4. 个性化只放外观选项，不混入调度设置。
5. 设置只放长期偏好、安全保护和文件位置。
```

## 配置边界

- 本地应用配置是自动调度的唯一运行时匹配源。
- 机型策略包是可组合、可迁移、可分享的配置容器；从包中移出应用配置不会删除本地配置。
- 导入社区机型策略包时，包内配置会按用户确认导入本地库，之后才参与调度。
- Profile、机型策略包、社区目录和迁移包都必须通过 Schema 版本校验；未来版本文件会被隔离并在状态中心提示，不会静默降级或覆盖。

## 规划中的功能入口

以下入口对应项目路线图的后续阶段，尚未全部实现。落地时仍按用户任务组织，不把传感器、算法或厂商接口直接暴露成一级菜单。

```text
控制台
├─ 目标体验
│  ├─ 目标帧率与稳定性
│  ├─ 温度与功耗上限
│  └─ 性能 / 省电 / 安静偏好
├─ 实时体验
│  ├─ 帧率与帧时间
│  ├─ CPU / GPU 温度、负载与功耗
│  └─ 调度前后效果摘要
└─ 自适应调度
   ├─ 观察模式
   ├─ 当前偏差与调节原因
   └─ 暂停并恢复静态配置

策略中心
├─ 应用配置编辑器
│  ├─ 目标体验
│  ├─ 受保护后台任务
│  └─ 多应用冲突规则
└─ 社区
   ├─ 设备匹配度与风险等级
   ├─ 复现成功率与回滚率
   └─ 本机验证结果

诊断中心
├─ 遥测能力与采集冲突
├─ 帧时间与硬件指标历史
├─ 资源争用分析
└─ Provider 状态与失败原因
```
