# Windows GPU 进程遥测

随芯调的 `windows.gpu-process` Provider 使用 Windows 自带的 GPU Engine 与 GPU Process Memory 性能计数器，对当前前台目标进程做只读观察。它不调用显卡超频接口，不修改频率、电压、功耗墙或驱动设置。

## 当前指标

- 进程 GPU 使用率：读取目标 PID 的所有 GPU Engine 实例，取最忙引擎的利用率并限制在 `0%` 到 `100%`。该值接近任务管理器的“最忙引擎”观察思路，不等同于整张显卡所有引擎利用率之和。
- 进程独占显存：汇总目标 PID 在多个适配器实例上的 `DedicatedUsage`，转换为 MiB。
- 进程共享显存：汇总目标 PID 在多个适配器实例上的 `SharedUsage`，转换为 MiB。

## 能力与降级

- Provider 最短采样间隔为 2 秒，避免把 Windows 性能计数器当作高频分析器。
- 设备、系统版本或驱动未公开对应计数器时，界面明确显示不可用。
- 目标进程尚未创建 GPU 设备或当前没有计数器实例时，返回“暂无 GPU 活动样本”，不会显示伪造的 `0`。
- GPU Engine 与 GPU Process Memory 分别检测；缺少其中一组不会拖垮另一组。
- 每个 Provider 独立失败，基础进程指标、PresentMon、历史写入、调度和回滚不受影响。

## 已知限制

微软说明 Windows 性能计数器用于管理和诊断，不适合快于每秒一次的高频采样。微软也记录过部分 Windows 10 / GPU 组合的每进程独显内存计数异常，因此当前显存值只作为诊断参考，不用于自动闭环或安全阈值判断。

当前 Provider 不提供温度、板卡功耗、核心频率、电压或风扇转速。这些值通常需要厂商 API、驱动接口或硬件监控服务，后续必须通过独立能力检测和可隔离 Provider 接入。
