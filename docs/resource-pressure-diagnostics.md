# 资源压力摘要

诊断中心的“资源压力”是对本次只读遥测结果的快速提示，不是自动调度指令，也不会修改电源方案、进程优先级、频率或电压。

## 判断范围

- CPU 使用率优先使用 Windows 系统硬件 Provider 的整机 CPU 使用率。
- GPU 使用率使用整机最忙 GPU 引擎利用率；如果可用，也会参考 NVIDIA NVML 的 GPU 利用率。
- 多个 Provider 同时提供同一类指标时取较高的有效值，避免把瞬时高负载隐藏掉。
- 只有状态为 `Collected` 的 Provider 样本会进入压力、争用、历史对比和趋势分析；失败、不可用、限流、预热或超时样本中的残留指标会被忽略。
- 无有效 CPU/GPU 使用率样本时显示“未知”，不会用温度、显存容量或功耗猜测压力。
- 遥测历史直接从已保存的原始指标重新计算压力摘要，不额外复制压力字段，因此旧版数据库无需迁移。

## 当前分级

| 级别 | 最高有效 CPU/GPU 使用率 |
| --- | --- |
| 低 | 小于 75% |
| 中 | 75% 至小于 90% |
| 高 | 90% 及以上 |

这些阈值用于让用户快速判断当前是否值得进一步观察，不能替代游戏帧时间、温度、功耗和应用自身指标。后续如果接入自适应调度，应在独立的安全策略中加入滞回、冷却时间和回滚，而不是直接复用这个显示等级作为硬件控制命令。

## 前台与整机对照

诊断中心还会把前台进程使用率与整机使用率并列显示：

- 整机达到 75% 且整机与前台差值达到 25 个百分点时，提示“有争用迹象”。
- 整机达到 90% 且差值达到 40 个百分点时，提示“后台争用较高”。
- 如果整机很高但前台进程也占用了大部分资源，则不会误报为后台争用。
- 缺少一组完整的前台/整机指标时显示“未知”，不会根据不完整数据限制后台程序。

## 资源建议

前台/整机对照会进一步给出保守的文字建议：

- “建议检查后台负载”：整机压力较高，且前台占用与整机占用存在明显差距。
- “主要由前台应用占用”：整机压力较高，但前台应用已经承担了大部分负载，不建议仅凭这次观察限制后台。
- “暂时无需处理”：当前没有足够证据表明存在后台争用。
- “证据不足，暂不判断”：缺少可配对的前台或整机指标。

这些文字只帮助用户决定下一步是否检查后台应用、帧时间、温度或功耗，不会直接生成进程限制、电源切换或 GPU 控制动作。遥测历史会同时保留压力、争用和建议摘要，便于回看一次观察时是否存在后台负载证据。

## 同应用对比

完成过至少两次同一前台进程的观察后，诊断中心会显示当前值相对上一次同应用观察的指标变化。对比按进程名、Provider 来源和指标类型配对，不会把不同应用、不同来源或不同指标强行相减；同一来源缺少历史值时会明确提示。

对比和趋势只使用当前观察时间之前的有效样本；未来时间戳可能来自时钟回拨、测试数据或异常写入，不会被当成“上一次”或当前趋势的一部分。在同一批历史中存在至少两个有效样本时，诊断中心还会显示基础趋势摘要：样本数、均值、最小值、最大值和相对首个样本的上升/下降/稳定方向。趋势只用于帮助用户判断是否值得继续观察，不代表因果关系，也不会直接触发调度动作。

如果存在同一应用最近一次成功调度，诊断中心会尝试按时间找到调度前和调度后的样本，并显示同源指标差值。找不到任一侧样本、最近运行失败或前后 Provider 不一致时会明确降级；这只是时间上的效果观察，不等同于证明调度造成了变化。
